# Vibe Coding: ساختن محصول قابل‌اعتماد با هوش مصنوعی

> **نوع سند:** دستورالعمل
> **هدف این سند:** مراحلی که بعد از طراحی، سایت را به یک محصول سالم، امن و منتشرشده تبدیل می‌کند.
> **موضوع تحقیق:** فرایند کامل ساخت اپ و سایت با ابزارهای هوش مصنوعی، فراتر از نوشتن کد.
> **منابع:** [S18 مقاله‌ی Opinion AI](../../../sources/README.md#s18)
> **آخرین بررسی:** ۲۰۲۶-۱۰-۱۶
> **دفعه‌ی بعد چک شود:** بخش پولی مقاله (فقط بخش رایگان خوانده شد)؛ ابزارهای جدید معرفی‌شده.

---

## ایده‌ی اصلی

✅ ساختن یک اپ یا سایت قابل‌اعتماد فقط تولید کد نیست. طبق مقاله: باید ابزار مناسب را انتخاب کنی، قبل از اجرا برنامه‌ریزی کنی، قابلیت‌ها را یکی‌یکی بسازی، نسخه‌های سالم را نگه داری، خطاها را بررسی کنی، امنیت را جدی بگیری و محصول را در محیط واقعی آزمایش کنی.

بهترین راه یادگیری حفظ کردن پرامپت نیست؛ ساختن یک پروژه‌ی واقعی و حل کردن مشکلاتش است.

## Git: دکمه‌ی «برگشت» تو

🧭 Git هر نسخه‌ی سالم را ذخیره می‌کند. اگر تغییر بعدی چیزی را خراب کرد، به نسخه‌ی قبل برمی‌گردی.

```text
This folder is not under version control yet. Initialize a git repository, add a
sensible .gitignore, and commit the current working state with a clear message.
From now on, after each checkpoint I approve, commit it with a message that says
what changed.
```

## امنیت

✅ طبق مقاله، برای هر اپی که با کاربران، اطلاعات خصوصی، اشتراک، سوابق کسب‌وکار یا پرداخت سروکار دارد، نباید هر چیزی را که هوش مصنوعی تحویل می‌دهد چشم‌بسته قبول کرد.

چک‌لیست حداقلی برای یک سایت 🧭:
- [ ] هیچ کلید API، رمز یا توکنی در کد سمت مرورگر یا در مخزن عمومی نیست
- [ ] فرم‌ها در برابر اسپم محافظت دارند
- [ ] ورودی کاربران قبل از ذخیره یا نمایش پاک‌سازی می‌شود
- [ ] سایت روی HTTPS است
- [ ] کتابخانه‌ها از منبع رسمی و نسخه‌ی مشخص بارگذاری می‌شوند

```text
Run a security review of this site: look for exposed API keys or secrets, unsafe
handling of form input, missing spam protection, third-party scripts loaded without a
pinned version, and anything that sends user data somewhere unexpected. Rank findings
by risk and wait before fixing.
```

# چک‌لیست امنیت پیش از انتشار سایت و اپ

> **نوع سند:** دستورالعمل
> **هدف این سند:** پیش از انتشار هر سایت یا اپی که با هوش مصنوعی ساخته شده، جلسه با یک فهرست ثابت همه‌ی محافظت‌های پایه را اجرا، آزمون و گزارش کند.
> **موضوع تحقیق:** ویدیوی «۲۷ موضوع امنیتی برای اپ ساخته‌شده با وایب‌کدینگ» که کاربر فرستاد؛ سنجیده با OWASP Top 10:2025.
> **منابع:** [S223 ویدیوی ۲۷ موضوع و OWASP](../../sources/README.md#s223)
> **آخرین بررسی:** ۲۰۲۶-۱۱-۰۱
> **دفعه‌ی بعد چک شود:** نسخه‌ی تازه‌ی OWASP Top 10؛ هر بار که پروژه‌ی واقعی ایرادی پیدا کرد که این فهرست نگرفت.

## ۱. فهرست ۲۷ موردی
🧭 فهرست از ویدیو آمده و با کلمه‌های خودمان نوشته شده. هر مورد را با آزمون واقعی ثابت کن، نه با گفته‌ی عامل.

**ورود و حساب**
1. احراز هویت درست (مسیرهای خصوصی بدون ورود باز نشوند).
2. رمزها با هش مخصوص رمز (Argon2 یا bcrypt)، هرگز متن ساده.
3. کوکی نشست با `HttpOnly`، `Secure` و `SameSite`.
4. محافظت CSRF برای درخواست‌های تغییردهنده.
5. لینک بازیابی رمز، زمان‌دار و یک‌بارمصرف.
6. سقف تلاش ورود (rate limit).
7. مسیرهای مدیر فقط با نقش مدیر؛ بقیه 403.

**داده و ورودی**
8. پایگاه داده فقط از سمت سرور، با مجوز هر ردیف (مثل RLS).
9. کوئری پارامتردار، نه چسباندن متن.
10. اعتبارسنجی فرم‌ها در سرور؛ بررسی مرورگر کافی نیست.
11. جلوگیری از XSS (خروجی escape شده و CSP).
12. آپلود: محدودیت نوع و حجم؛ فایل اجرایی رد شود.
13. قیمت و پرداخت در سرور محاسبه شود؛ عدد مرورگر پذیرفته نشود.

**رازها**
14. کلید API فقط در سرور و `.env`، نه در کد مرورگر.
15. متغیرهای محیطی بازبینی شوند: راز با پیشوند عمومی به مرورگر نرود.
16. جستجوی فایل‌های لورفته در نشانی‌های عمومی (`/.env`، `/backup.zip`، `/.git/config` باید 404 بدهند).
17. اسکن تاریخچه‌ی git برای راز.
18. هر کلید لورفته باطل و عوض شود؛ پاک کردن از کد کافی نیست.

**پیکربندی**
19. HTTPS اجباری با TLS به‌روز و HSTS.
20. CORS فقط برای دامنه‌های خودمان.
21. هدرهای امنیتی: CSP، HSTS، `X-Frame-Options`، `X-Content-Type-Options`.
22. حالت debug در نسخه‌ی اصلی خاموش؛ پیام خطا بدون جزئیات داخلی.

**بسته‌ها و پایش**
23. به‌روزرسانی بسته‌های آسیب‌پذیر ([سه لحظه‌ی امنیت](README.md)).
24. حذف بسته‌های بی‌استفاده.
25. ثبت رویدادهای مشکوک با هشدار (مثل چند ورود ناموفق پیاپی).

**پایان کار**
26. بررسی امنیتی کامل کد.
27. آزمون همه‌ی محافظت‌ها و گزارش: چند ایراد پیدا شد، چند تا رفع شد.

## ۲. چیزهایی که ویدیو نگفته است 🧭
- ⛔ **کنترل دسترسی هر رکورد (IDOR):** کاربر با عوض کردن شناسه در نشانی نباید داده‌ی نفر دیگر را ببیند. ✅ این بالاترین ریسک OWASP است (A01:2025 Broken Access Control، https://top10.owasp.org/2025) و قفل مسیر مدیر آن را پوشش نمی‌دهد.
- **زنجیره‌ی تأمین:** ✅ A03:2025؛ فایل قفل، نسخه‌ی ثابت و بررسی بسته‌ی تازه، نه فقط به‌روزرسانی ([README](README.md)).
- **نسخه‌ی پشتیبان و آزمون بازگرداندن آن.**
- **سقف درخواست برای همه‌ی APIهای گران،** نه فقط ورود؛ مخصوصاً مسیرهایی که به مدل هوش مصنوعی یا پیامک وصل‌اند.
- **تزریق پرامپت:** اگر محصول دستیار هوش مصنوعی دارد، متن کاربر نباید بتواند به ابزارها و داده‌ی دیگران دستور بدهد.
- **وابستگی به اسکرین‌شات‌ها:** ویدیو نشان می‌دهد همه‌ی ایرادها رفع شد، ولی یک پرامپت امنیت را ثابت نمی‌کند؛ هر مورد آزمون قابل اجرا می‌خواهد.

## ۳. پرامپت (نوشته‌ی خودمان)
```text
Run a pre-launch security pass on this project using domains/security/pre-launch-checklist.md from the
knowledge library. First read STATE.md and keep every project constraint. For each item: inspect the code,
state pass, fail or not applicable with file and line, fix what fails in small commits, and add a runnable
test that proves the protection (including per-record access with a second user). Do not print secret values.
If a secret leaked, list it by name and tell me which key to revoke. End with a report: found, fixed, not
tested, and anything that needs my decision.
```

## ۴. هشدار درباره‌ی منبع
ویدیو برای گرفتن «کیت کامل» می‌گوید «وایب» را کامنت کن، پس قیف فروش یا جذب است. لازم نیست؛ فهرست بالا کافی است. نام سازنده در فایل نبود.

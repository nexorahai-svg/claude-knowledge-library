# هزینه و کارایی Claude Code

> **نوع سند:** دستورالعمل
> **هدف این سند:** کم کردن هزینه و مصرف سقف Claude Code بدون پایین آمدن کیفیت: اول اندازه‌گیری، بعد اهرم‌ها به ترتیب، بعد سقف.
> **موضوع تحقیق:** قیمت رسمی مدل‌ها، تنظیمات هزینه در مستندات رسمی Claude Code، و ابزارهای جانبی کاهش توکن.
> **منابع:** [S25 مستندات هزینه و قیمت رسمی](../../sources/README.md#s25) · [S24 ابزارهای جانبی](../../sources/README.md#s24) · [S79 Ponytail](../../sources/README.md#s79)
> **آخرین بررسی:** ۲۰۲۶-۱۰-۱۸
> **دفعه‌ی بعد چک شود:** جدول قیمت؛ صفحه‌ی costs در مستندات Claude Code؛ نسخه‌ی لازم برای قابلیت‌ها؛ وضعیت «آزمایشی» advisor و fast mode.

## اصل اول: صورت‌حساب = قیمت × حجم

🧭 قیمت را نمی‌توانی عوض کنی؛ حجم توکن را می‌توانی. Claude Code در هر درخواست **کل گفتگو** را دوباره می‌فرستد، پس یک سؤال یک‌خطی در انتهای یک جلسه‌ی طولانی هم هزینه‌ی همه‌ی متن بالایش را می‌دهد (از کش ارزان‌تر، ولی نه رایگان).

## قدم ۱: اندازه بگیر

✅ (https://code.claude.com/docs/en/costs)
- **`/usage`** در پایان یک جلسه‌ی واقعی: هزینه‌ی تخمینی، تفکیک بر اساس مدل (ورودی، خروجی، نوشتن و خواندن کش)، و خط «Prompt cache (main)» با درصد استفاده از کش و گرم یا سرد بودنش (نسخه‌ی 2.1.251 به بعد). روی Pro، Max، Team و Enterprise مصرف را به skillها، زیرعامل‌ها، افزونه‌ها و MCPها نسبت می‌دهد. عدد دلاری **تخمین محلی با قیمت فهرست** است؛ عدد قطعی در صفحه‌ی Usage کنسول است.
- **`/context`**: نقشه‌ی رنگی اینکه چه چیزی context را پر کرده.
- **[ccusage](../../catalog/ccusage.md)**: گزارش روزانه و جلسه‌ای از لاگ‌های محلی.
- مرجع مقایسه ✅: در استقرارهای سازمانی، میانگین حدود **۱۳ دلار برای هر توسعه‌دهنده در هر روز کاری** است و ۹۰٪ کاربران زیر ۳۰ دلار می‌مانند. (میانگین سازمانی است، نه هدف.)

🧭 برای یک کار تکراری سه عدد یادداشت کن: کل هزینه، تفکیک مدل‌ها، و تعداد اصلاح‌هایی که لازم شد. این خط مبنای همه‌ی تغییرهاست.

## قدم ۳: هزینه‌های پنهان (وقتی پشت کامپیوتر نیستی)

✅ از مستندات هزینه:
- **کارهای زمان‌بندی‌شده و loopها:** هر اجرا کل context را می‌فرستد، حتی وقتی جلسه بیکار است.
- **پیگیری‌های `/goal`:** به‌طور پیش‌فرض هر ۳۰ دقیقه؛ با `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` خاموش.
- **پیام از جلسه‌های دیگر:** هر پیام یک نوبت تازه با کل context؛ با `crossSessionInbound: hold` نگه داشته می‌شوند.
- **زیرعامل‌ها و workflowها:** درخواست‌های خودشان را جدا می‌فرستند.
- **تیم عامل‌ها:** در حالت plan حدود **۷ برابر** یک جلسه‌ی عادی توکن مصرف می‌کنند. تیم کوچک، Sonnet برای هم‌تیمی‌ها، و خاموش کردن هم‌تیمی‌ها بعد از کار.

در `/usage` بخش نسبت‌دهی و ردیف‌های loop را نگاه کن؛ هر چیزی که فراموشش کرده بودی، اولین چیزی است که باید متوقف شود.

## قدم ۴: سقف بگذار

✅ (https://code.claude.com/docs/en/cli-reference) برای اجراهای بدون حضور تو، فقط در حالت print (`-p`):
- `--max-budget-usd`: وقتی هزینه‌ی **تخمینی خود Claude Code** به سقف برسد متوقف می‌شود؛ ممکن است کمی بیشتر شود، جا بگذار. هزینه‌ی زیرعامل‌ها حساب می‌شود.
- `--max-turns`: سقف تعداد نوبت؛ به‌طور پیش‌فرض نامحدود.

برای حساب‌ها: سقف هزینه‌ی workspace در کنسول (API)، سقف هزینه در Team/Enterprise، و در Pro/Max تنظیم usage credits.

## روش اثبات صرفه‌جویی

🧭
1. یک کار تکراری و قابل تأیید انتخاب کن (مثلاً رفع یک باگ با تست شکست‌خورده)
2. در جلسه‌ی تازه اجرا کن؛ `/usage`، زمان و تعداد اصلاح را ثبت کن
3. **فقط یک چیز** را عوض کن
4. همان کار را با همان پرامپت در جلسه‌ی تازه تکرار کن
5. تغییر را فقط وقتی نگه دار که هزینه کم شد **و** کیفیت بدون اصلاح بیشتر ماند؛ دوباره‌کاری هم هزینه است

## پرامپت: ممیزی تنظیمات هزینه

```text
Audit my Claude Code cost setup without changing anything. Check: the effort level in
effect for my current model (including CLAUDE_CODE_EFFORT_LEVEL and modelSettings),
whether a top-level effortLevel is being ignored, which model the Explore subagent and
my custom subagents use, the size of my CLAUDE.md files, which MCP servers are enabled
but unused, any scheduled tasks, loops or goal check-ins, and whether fast mode is on.
Then list the changes that would cut cost, ranked by expected saving, and wait.
```

## فاصله‌ی ادعای پست با مستندات

✅ راهنمای ۱۰ مرحله‌ای پست منبع (P02) در کل دقیق بود. اختلاف‌ها:
- «عوض کردن effort کش را نگه می‌دارد» فقط روی مدل‌های نسل ۵.۵ و Fable 5.1 درست است، نه همه‌ی مدل‌ها.
- متغیر اجبار مدل زیرعامل‌ها (`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`) **به‌تنهایی کاری نمی‌کند**؛ باید `CLAUDE_CODE_SUBAGENT_MODEL` هم تنظیم شده باشد.
- شرط advisor «تله‌متری روشن» نیست، بلکه «دریافت feature flagها» است (که با `DISABLE_TELEMETRY` خاموش می‌شود).
- fast mode «فقط API مستقیم» نیست: اشتراک‌ها هم (از طریق usage credits) دارند؛ Bedrock، Vertex، Foundry و Claude Platform on AWS ندارند. ✅ در صفحه‌ی قیمت API، fast mode روی Opus 5.5 دیگر «پیش‌نمایش» نامیده نمی‌شود، ولی مستندات Claude Code هنوز «research preview» می‌گوید.
- پست Jev (مدل تصمیم‌گیری TypeSafe) را به‌عنوان مرحله‌ی ۱۱ پیشنهاد داده بود: ⛔ [کارت jev-guard](../../catalog/jev-guard.md).

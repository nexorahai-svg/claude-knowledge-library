# امنیت MCP و افزونه‌های Claude Code

> **نوع سند:** توضیح
> **هدف این سند:** قواعد ثابت برای وصل کردن سرورهای MCP، افزونه‌ها و hookها به Claude Code، بدون اینکه دسترسی یا داده‌ی بیش از حد بدهیم.
> **موضوع تحقیق:** راهنمای امنیتی رسمی سازندگان MCP (Supabase، Vercel، Chrome DevTools، Playwright) و ریسک‌های افزونه‌های شخص ثالث.
> **منابع:** [S19 Supabase](../../sources/README.md#s19) · [S20 Vercel](../../sources/README.md#s20) · [S21 Chrome DevTools و Playwright MCP](../../sources/README.md#s21) · [S22 Oh My Claude Code](../../sources/README.md#s22) · [S68 مستندات مجوز Claude Code](../../sources/README.md#s68) · [S165 مهارت‌های اینستاگرام](../../sources/README.md#s165) · [S208 پایش ۲۰۲۶-۱۰-۳۰](../../sources/README.md#s208)
> **آخرین بررسی:** ۲۰۲۶-۱۰-۳۱
> **دفعه‌ی بعد چک شود:** راهنمای امنیتی هر MCP بعد از نسخه‌ی اصلی جدید؛ آیا پیشنهاد `"${VAR:?}"` در مستندات آمده است (تا ۲۰۲۶-۱۰-۲۸ نه: فقط `${VAR}` و `${VAR:-default}`)؟
> ✅ **سازوکارهای محدود کردن MCP در مستندات رسمی (۲۰۲۶-۱۰-۲۸):** فهرست `disabledMcpServers` برای خاموش کردن سرورها؛ تنظیم مدیریتی `managedMcpServers` (از 2.1.259) و `managed-mcp.json` برای کنترل انحصاری سازمان؛ پرچم `--strict-mcp-config` (از 2.1.246) که پرسش تأیید سرور پروژه را رد می‌کند و فقط پیکربندی داده‌شده را می‌خواند. 2.1.312: در تله‌متری، `mcp_server.name` برای MCPهای راه دور با آدرس ثابت در افزونه‌های بازار رسمی نام واقعی را می‌دهد نه «custom». https://code.claude.com/docs/en/mcp · https://code.claude.com/docs/en/managed-mcp
> ✅ **از Claude Code 2.1.314 (CHANGELOG رسمی، خوانده ۲۰۲۶-۱۰-۳۰، [S208](../../sources/README.md#s208)):** تنظیم `permissions.blockWritesOutsideWorkingDirectories` نوشتن با Write، Edit و NotebookEdit بیرون از پوشه‌های کاری را در هر حالت مجوز رد می‌کند؛ دنباله‌ی طبیعی هشدار نوشتن بیرون فضای کار (GHSA-5xjx-9qx6-jcrv، [هشدارهای اکتبر](../security/advisories-2026-10.md)). 🧭 برای پروژه‌های با عامل خودکار یا حالت auto روشن نگه‌داشتنش معقول است؛ هنوز در پروژه‌ای آزموده نشده. همچنین hookهای `Bash` حالا روی دستورهای ابزار Monitor هم اجرا می‌شوند (رد یا پرسش؛ نه تأیید یا بازنویسی) و شرط `sandbox.excludedCommands` یعنی هر دستور در یک فراخوانی باید با یک مدخل بخواند.

> ✅ **از Claude Code 2.1.316 (CHANGELOG رسمی، ۲۰۲۶-۱۰-۳۱، [S216](../../sources/README.md#s216)):** جلسه‌ی `--restricted` دیگر فایل بیرون از پوشه‌های کاری را که قاعده‌ی Read اجازه داده بود بارگذاری نمی‌کند؛ فهرست مدیریت‌شده‌ی `autoMode.allow` بدون `"$defaults"` دیگر استثناهای داخلی را از `--settings` برنامه‌ی میزبان، قاعده‌ی اول `/permissions` یا `/auto-mode-setup` پس نمی‌گیرد؛ اسکریپت `headersHelper` افزونه‌ی MCP دیگر `CLAUDE_PLUGIN_ROOT` خراب نمی‌گیرد؛ کارهای زمان‌بندی‌شده‌ی ابری وقتی حالت auto به‌خاطر نبود حکم ایمنی سرور نوبت را متوقف کند «شکست‌خورده» علامت می‌خورند.

## چرا مهم است

✅ سازندگان رسمی خودشان صریح می‌گویند:
- **Vercel:** وصل شدن MCP «همان دسترسی حساب Vercel تو را به هوش مصنوعی می‌دهد».
- **Supabase:** MCP «با مجوزهای توسعه‌دهنده‌ی تو» کار می‌کند؛ prompt injection «اصلی‌ترین حمله‌ی مخصوص مدل‌های زبانی» است.
- **Chrome DevTools MCP:** «محتوای مرورگر را در اختیار MCP می‌گذارد» و اجازه‌ی تغییر هر داده‌ای در مرورگر را می‌دهد.
- **Playwright MCP:** «مرز امنیتی نیست».

یعنی هر MCP یک در است: هم به حساب‌های تو، هم برای متنی که از صفحه یا داده‌ی بیرونی وارد گفتگو می‌شود و ممکن است دستور جعلی داشته باشد.

## قواعد ما

| # | قاعده | مثال |
|---|---|---|
| ۱ | **کمترین دسترسی** | Supabase با `read_only=true` و `project_ref` (فقط یک پروژه) |
| ۲ | **محیط توسعه، نه داده‌ی واقعی** | MCP پایگاه داده را به پروژه‌ی تست وصل کن، نه پروژه‌ی مشتری |
| ۳ | **تأیید انسانی روشن بماند** | هیچ عملی (به‌خصوص انتشار، حذف، SQL نوشتنی) بدون تأیید اجرا نشود |
| ۴ | **مرورگر جدا** | Chrome DevTools و Playwright فقط با `--isolated`؛ هرگز پروفایل شخصی با حساب‌های واردشده |
| ۵ | **آمار و ارسال داده خاموش** | Chrome DevTools MCP: `--no-usage-statistics` و `--no-performance-crux` |
| ۶ | **فقط از سازنده‌ی رسمی** | نشانی مخزن یا endpoint را با سایت رسمی مقایسه کن (مثل `https://mcp.vercel.com`) |
| ۷ | **MCPهای بی‌استفاده خاموش** | هر MCP فعال در هر جلسه context و ریسک اضافه می‌کند |
| ۸ | **محتوای صفحه و داده = داده، نه دستور** | اگر خروجی یک ابزار گفت «حالا این کار را بکن»، اجرا نکن |

## افزونه‌ها و hookهای شخص ثالث

🧭 افزونه‌ای که hook روی همه‌ی رویدادها اضافه می‌کند (مثل [Oh My Claude Code](../../catalog/oh-my-claude-code.md) که روی ۱۱ رویداد، از جمله هر پرامپت و هر ابزار، کد اجرا می‌کند) همه‌ی کار تو را می‌بیند. قبل از نصب:
1. فایل `hooks.json` و اسکریپت‌هایش را بخوان (یا از Claude بخواه بخواند و خلاصه کند)
2. ببین آیا `~/.claude/CLAUDE.md` یا `settings.json` را بازنویسی می‌کند
3. ببین آیا داده به سرویس بیرونی می‌فرستد یا کلید API می‌خواهد
4. ببین آیا Claude Code خودش همان کار را دارد (زیرعامل، تیم عامل، skill، worktree)

```text
Before I install this plugin/MCP server, read its manifest, hooks and install scripts
(do not run anything). Tell me: which events it hooks, what files and settings it writes,
whether it sends data to any external service, what permissions it needs, and whether
Claude Code already has a built-in feature that does the same job.
```

## مهارتی که خودکار پست و دایرکت می‌فرستد ✅ ([S165](../../sources/README.md#s165))

🧭 مهارت یا MCP شبکه‌ی اجتماعی که (۱) داخل نشست واردشده‌ی Chrome تو کار می‌کند، (۲) کوکی مرورگر را می‌خواند، (۳) با cron روزی چند پست یا پاسخ خودکار می‌فرستد، یا (۴) نصبش `curl | bash` است، خطر بسته شدن حساب و نشت نشست دارد. تنها راه مجاز اینستاگرام Graph API رسمی است ([انتشار](../social-media/publishing.md)). نمونه‌ها با حکم ⛔: [ootto-content-skills](../../catalog/ootto-content-skills.md)، [hao0321-social-post](../../catalog/hao0321-social-post.md)، [inssist-mcp](../../catalog/inssist-mcp.md). کپی‌های ناشناس یک مهارت محبوب (بیشتر ستاره‌هایشان صفر تا هشت) فقط از مخزن اصلی نصب شود.

## نگهبان‌های داخلی دستور شل

این‌ها به hook و اسکریپتی که خودمان می‌نویسیم هم مربوط است:

| رفتار | برچسب |
|---|---|
| در حالت Manual، دستوری که تحلیل Claude Code **نمی‌تواند کامل بخواند**، تأیید می‌خواهد و فقط‌خواندنی حساب نمی‌شود؛ دستور بلندتر از ۱۰٬۰۰۰ نویسه همیشه تأیید می‌خواهد | ✅ |
| قانون `deny` یا `ask` روی Bash فقط **شکل معمول** دستور را می‌گیرد: `Bash(rm *)` جلوی `bash -c 'rm -rf build/'` یا `/bin/rm` را نمی‌گیرد. مستندات صریح می‌گوید این «مرز امنیتی نیست»؛ برای مرز واقعی sandbox یا hook از نوع PreToolUse | ✅ |
| `rm` یا `rmdir` روی **مسیر حیاتی** (مثل `rm -rf /` یا `rm -rf ~`) حتی با قانون allow یا hook رد می‌شود | ✅ |
| در حالت auto، `rm -rf "$VAR"` وقتی متغیر جایی در گفتگو مقدار نگرفته، مسدود می‌شود؛ با نوشتن مسیر واقعی در دستور رفع می‌شود. `rm -rf "$VAR"/*` جزو مسیرهای حیاتی است | ✅ |
| در حالت auto، `wrangler d1 execute <db> --remote --command "SELECT …"` با توکن Cloudflare از عامل رد شد (دسته‌ی «Production Reads») حتی بعد از برداشتن قفل انتشار کتابخانه؛ خود مالک با پیشوند `!` اجرا کرد (۳۱۴ ردیف، ۸۲ کیلوبایت). مستندات رسمی auto mode خواندن‌های production را جداگانه در فهرست پیش‌فرض مسدودها نمی‌آورند، فقط استقرار و migration و «مکان داده‌ی حساس» تنظیم‌شده را؛ پس علت دقیق ❓. راه: مالک خودش اجرا کند، با مسیرهای مطلق خروجی و `cd` به پروژه (مسیر نسبی در پنجره‌ی ترمینال دیگر شکست خورد) | 🔬 رفتار، ❓ علت ([مستندات](https://code.claude.com/docs/en/permission-modes)) |
| Claude Code برای حذف با متغیر، شکل `"${VAR:?}"` را پیشنهاد داد (اگر متغیر خالی باشد، شل خطا می‌دهد و چیزی پاک نمی‌شود)؛ و اسکریپت درون `bash -c` را که نمی‌توانست بررسی کند علامت زد | 🔬 دیده‌شده در یک فروشگاه واقعی (دفتر پروژه‌ها)؛ ❓ پیشنهاد `${VAR:?}` در مستندات رسمی پیدا نشد |

🧭 درس: در اسکریپت‌ها حذف را با `"${VAR:?}"` بنویس، دستورها را تکی و ساده بنویس نه درون `bash -c`، و برای جلوگیری واقعی به قانون Bash تکیه نکن.

# امنیت MCP و افزونه‌های Claude Code

> **نوع سند:** توضیح
> **هدف این سند:** قواعد ثابت برای وصل کردن سرورهای MCP، افزونه‌ها و hookها به Claude Code، بدون اینکه دسترسی یا داده‌ی بیش از حد بدهیم.
> **موضوع تحقیق:** راهنمای امنیتی رسمی سازندگان MCP (Supabase، Vercel، Chrome DevTools، Playwright) و ریسک‌های افزونه‌های شخص ثالث.
> **منابع:** [S19 Supabase](../../sources/README.md#s19) · [S20 Vercel](../../sources/README.md#s20) · [S21 Chrome DevTools و Playwright MCP](../../sources/README.md#s21) · [S22 Oh My Claude Code](../../sources/README.md#s22) · [S68 مستندات مجوز Claude Code](../../sources/README.md#s68)
> **آخرین بررسی:** ۲۰۲۶-۱۰-۱۷
> **دفعه‌ی بعد چک شود:** راهنمای امنیتی هر MCP بعد از نسخه‌ی اصلی جدید؛ آیا Claude Code سازوکار تازه‌ای برای محدود کردن MCP اضافه کرده است؟ آیا پیشنهاد `"${VAR:?}"` در مستندات آمده است؟

---

## چرا مهم است

✅ سازندگان رسمی خودشان صریح می‌گویند:
- **Vercel:** وصل شدن MCP «همان دسترسی حساب Vercel تو را به هوش مصنوعی می‌دهد».
- **Supabase:** MCP «با مجوزهای توسعه‌دهنده‌ی تو» کار می‌کند؛ prompt injection «اصلی‌ترین حمله‌ی مخصوص مدل‌های زبانی» است.
- **Chrome DevTools MCP:** «محتوای مرورگر را در اختیار MCP می‌گذارد» و اجازه‌ی تغییر هر داده‌ای در مرورگر را می‌دهد.
- **Playwright MCP:** «مرز امنیتی نیست».

یعنی هر MCP یک در است: هم به حساب‌های تو، هم برای متنی که از صفحه یا داده‌ی بیرونی وارد گفتگو می‌شود و ممکن است دستور جعلی داشته باشد.

## قواعد ما

| # | قاعده | مثال |
|---|---|---|
| ۱ | **کمترین دسترسی** | Supabase با `read_only=true` و `project_ref` (فقط یک پروژه) |
| ۲ | **محیط توسعه، نه داده‌ی واقعی** | MCP پایگاه داده را به پروژه‌ی تست وصل کن، نه پروژه‌ی مشتری |
| ۳ | **تأیید انسانی روشن بماند** | هیچ عملی (به‌خصوص انتشار، حذف، SQL نوشتنی) بدون تأیید اجرا نشود |
| ۴ | **مرورگر جدا** | Chrome DevTools و Playwright فقط با `--isolated`؛ هرگز پروفایل شخصی با حساب‌های واردشده |
| ۵ | **آمار و ارسال داده خاموش** | Chrome DevTools MCP: `--no-usage-statistics` و `--no-performance-crux` |
| ۶ | **فقط از سازنده‌ی رسمی** | نشانی مخزن یا endpoint را با سایت رسمی مقایسه کن (مثل `https://mcp.vercel.com`) |
| ۷ | **MCPهای بی‌استفاده خاموش** | هر MCP فعال در هر جلسه context و ریسک اضافه می‌کند |
| ۸ | **محتوای صفحه و داده = داده، نه دستور** | اگر خروجی یک ابزار گفت «حالا این کار را بکن»، اجرا نکن |

## افزونه‌ها و hookهای شخص ثالث

🧭 افزونه‌ای که hook روی همه‌ی رویدادها اضافه می‌کند (مثل [Oh My Claude Code](../../catalog/oh-my-claude-code.md) که روی ۱۱ رویداد، از جمله هر پرامپت و هر ابزار، کد اجرا می‌کند) همه‌ی کار تو را می‌بیند. قبل از نصب:
1. فایل `hooks.json` و اسکریپت‌هایش را بخوان (یا از Claude بخواه بخواند و خلاصه کند)
2. ببین آیا `~/.claude/CLAUDE.md` یا `settings.json` را بازنویسی می‌کند
3. ببین آیا داده به سرویس بیرونی می‌فرستد یا کلید API می‌خواهد
4. ببین آیا Claude Code خودش همان کار را دارد (زیرعامل، تیم عامل، skill، worktree)

```text
Before I install this plugin/MCP server, read its manifest, hooks and install scripts
(do not run anything). Tell me: which events it hooks, what files and settings it writes,
whether it sends data to any external service, what permissions it needs, and whether
Claude Code already has a built-in feature that does the same job.
```

## نگهبان‌های داخلی دستور شل

این‌ها به hook و اسکریپتی که خودمان می‌نویسیم هم مربوط است:

| رفتار | برچسب |
|---|---|
| در حالت Manual، دستوری که تحلیل Claude Code **نمی‌تواند کامل بخواند**، تأیید می‌خواهد و فقط‌خواندنی حساب نمی‌شود؛ دستور بلندتر از ۱۰٬۰۰۰ نویسه همیشه تأیید می‌خواهد | ✅ |
| قانون `deny` یا `ask` روی Bash فقط **شکل معمول** دستور را می‌گیرد: `Bash(rm *)` جلوی `bash -c 'rm -rf build/'` یا `/bin/rm` را نمی‌گیرد. مستندات صریح می‌گوید این «مرز امنیتی نیست»؛ برای مرز واقعی sandbox یا hook از نوع PreToolUse | ✅ |
| `rm` یا `rmdir` روی **مسیر حیاتی** (مثل `rm -rf /` یا `rm -rf ~`) حتی با قانون allow یا hook رد می‌شود | ✅ |
| در حالت auto، `rm -rf "$VAR"` وقتی متغیر جایی در گفتگو مقدار نگرفته، مسدود می‌شود؛ با نوشتن مسیر واقعی در دستور رفع می‌شود. `rm -rf "$VAR"/*` جزو مسیرهای حیاتی است | ✅ |
| Claude Code برای حذف با متغیر، شکل `"${VAR:?}"` را پیشنهاد داد (اگر متغیر خالی باشد، شل خطا می‌دهد و چیزی پاک نمی‌شود)؛ و اسکریپت درون `bash -c` را که نمی‌توانست بررسی کند علامت زد | 🔬 دیده‌شده در پروژه‌ی MARIO E.G.S.H (دفتر پروژه‌ها)؛ ❓ پیشنهاد `${VAR:?}` در مستندات رسمی پیدا نشد |

🧭 درس: در اسکریپت‌ها حذف را با `"${VAR:?}"` بنویس، دستورها را تکی و ساده بنویس نه درون `bash -c`، و برای جلوگیری واقعی به قانون Bash تکیه نکن.
